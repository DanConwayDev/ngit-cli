Examples:
    # every usable signer with npub, aliases, scope and active state
    ngit account whoami --json --offline
    # one ngit command, or one git command, as alice
    ngit --signer alice issue create --subject "Bug" --body "Details" --json
    git -c nostr.signer=alice push origin pr/topic
    # make a stored identity this repository's default, or the global one
    ngit account login --local alice
    ngit account login alice
    # interactive login; the secret goes to the credential store
    ngit account login -i
    ngit account login --nsec-file /private/key --profile alice
    # store an established NIP-46 session, or pair a remote signer
    ngit account login --nbunksec-file /private/connection --profile alice
    ngit account login --bunker-url bunker://...
    # save a profile for explicit use without selecting it
    ngit account login -i --profile ci --no-activate
    ngit account create --name "Alice" --json
    # one-shot key for CI; --nbunksec-file for a bunker session
    ngit --nsec-file /private/key <command>
    # forget the selected account; report remaining logins
    ngit account logout --json
    # retain the remote session for reactivation
    ngit account logout --keep-credentials
    # also delete identity nsecs (explicitly destructive)
    ngit account logout --all --forget

Choosing who signs:
  --signer and `nostr.signer` accept an alias, an npub or an exact cached
  profile name, for one command; `account login` changes the default.

  An alias is a profile saved with `login --profile NAME`; a name is the
  account's cached Nostr display name and must match exactly one account
  holding stored credentials.
  Selection fails closed when the selector is missing, ambiguous or backed
  by invalid credentials; it never falls back to another account. Never
  export or pass an nsec merely to switch between stored accounts.

Local signer socket (NIP-5F):
  An npub selects an identity; a profile selects its saved signing backend.
  --signer <npub> first asks the local socket for that exact account, even
  when another account is active in the signer app. The same rule applies
  to nostr.signer=<npub>. Use saved credentials only when the socket is
  disabled/absent or reports that it does not hold the account. A locked
  signer or other socket error fails without switching backend.

  Named profiles retain their connections, even when the socket holds the
  same npub. Explicit nsec/bunker credentials also bypass socket discovery.
  With no login selected, use the socket's active account as a fallback.
  Saved but inactive profiles do not prevent that fallback.

    ngit --signer <npub> issue create --subject "Bug" --body "Details"
    git -c nostr.signer=<npub> push origin pr/topic
    # pin the socket's current account and backend in a named profile
    ngit account login --socket --profile desktop
    # pin a particular socket account without changing the current login
    ngit account login <npub> --socket --profile desktop --no-activate
    ngit account login --local desktop
    ngit --signer desktop issue create --subject "Bug" --body "Details"
    ngit account whoami --offline --json

  Socket profiles store an npub and public backend binding, never a secret.
  They require auto or file storage. An unavailable socket profile fails;
  it never uses stored keys instead. Each command pins the requested npub,
  so changes to the signer app's active account cannot change its identity.
  socket is not reserved; it is a normal profile name.

  Default socket: ~/.local/share/nostr/signer.sock. nostr.signer-socket can
  override the path or disable it with false. whoami reports availability
  and the effective socket account (JSON: socket), with bounded probes.
  Unavailable socket profiles retain their name, npub, backend and error
  in JSON unavailable_profiles and in human-readable warnings.
  Logout removes saved profile bindings but cannot revoke the signer app.
  It can reveal the automatic socket fallback. Socket-only logout errors
  with guidance to manage the external account or disable socket signing.
  export-keys cannot export socket-held secrets. To disable socket signing:
    git config --global nostr.signer-socket false
    # repository settings take precedence over global settings
    git config nostr.signer-socket false

Secrets:
  Secrets go to the OS credential store, else ngit's user-only file store
  (--secret-storage auto|file|git-config, `NGIT_SECRET_STORAGE`, or
  `nostr.secret-storage`). Only explicit `git-config` mode writes a
  plaintext secret to git config. Prefer --nsec-file and --nbunksec-file to
  inline values: they keep secrets out of process arguments, and work on
  any command as a one-shot identity for CI.

Remote signers (NIP-46):
  When you scan ngit's QR code or copy its nostrconnect:// URI, your signer
  must return the pairing secret. For a signer that only replies with "ack",
  use the bunker:// URI from the signer:
    ngit account login --bunker-url bunker://...

  A fresh pairing needs interactive approval, so unattended runs use an
  established connection. An nbunksec is one in portable form: it holds no
  npub, so the identity is resolved from the signer. A fresh login replaces
  the default remote session for that npub; use --profile NAME to keep
  several connections for one npub or to replace one named connection. An
  existing nsec is preserved. --no-activate saves a profile for explicit
  --signer use without selecting it.

Logging out and deleting keys:
  Plain `logout` forgets the repository-specific account when one is
  selected, otherwise the default account. Removing a repository override
  makes a remaining default account active: read the reported account
  before signing again. --local and --global restrict the scope.
  Credentials shared with other repositories go too.

  Deleting an identity nsec fails before any change, without a prompt,
  unless --forget authorizes it; --keep-credentials clears only the
  selection. Remote-session credentials need no --forget. `logout <npub>`
  and `forget-keys <npub>` target every credential and profile of that
  identity, and `forget-keys` deletes identity keys without further
  confirmation; `forget-keys signer:<npub>` removes only the default
  remote session. `logout --all` does not search other repositories or
  revoke remote signer permissions.

  Guide: https://ngit.dev/accounts
