Input:
  --set-file reads a JSON map of unique secret names to string values;
  --set-from-env NAME reads each value from that environment variable.
  Sets and removals can be combined in one atomic update. Values are never
  accepted on the command line, printed, or written to ngit's cache.

  The signer must be a confirmed maintainer with their own repository
  announcement. ngit encrypts to the coordinator's live advertised secret
  key and requires acknowledgement from one of its advertised inboxes.

Confirmation:
  After delivery ngit waits (--confirmation-timeout, default 90 seconds;
  0 publishes only) for a new coordinator status showing the change. JSON
  reports `confirmation` as `accepted` or `pending`, with
  `confirmation_event`. A passed deadline leaves it pending, not rejected,
  and the exit code is still 0 because publication succeeded: automation
  that needs acceptance must read `confirmation`. Do not republish just
  because the wait expired: check later with `ngit ci service status` or
  `ngit ci inspect --kind 39844`. `confirmation_event` is a raw hex ID.
  Confirmation is inventory evidence, not proof that a credential works.
